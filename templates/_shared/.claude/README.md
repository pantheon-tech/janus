# .claude/

Claude Code project-level configuration for this workspace.

- `settings.json` — permissions, env, worktree config, **hooks** wiring (generated by janus scaffold; permissions block is the single source of truth)
- `hooks/` — session lifecycle and worktree management hooks (rendered from janus templates at scaffold time, then customisable)
- `skills/` — project-scope skills (rendered from janus templates; project skills override user-scope skills with the same name)
- `reconcile.config.example` — copy to `reconcile.config` and add ERE patterns for `session-end.sh` to grep against memory files

## Hooks (4 ship with the scaffold)

| Hook | Event | Purpose |
|---|---|---|
| `session-start.sh` | SessionStart (`startup\|clear\|compact`) | Fetch remote, report branch divergence, list active worktrees + open PRs, re-inject CRITICAL rules on compaction |
| `session-end.sh` | SessionEnd | Advisory reconciliation: uncommitted/unpushed/orphaned-worktrees + config-driven stale-term grep against memory; writes a `last-session.json` breadcrumb |
| `setup-worktree.sh` | WorktreeCreate | Branches an agent worktree from `origin/<base_branch>` under `.claude/worktrees/<name>` |
| `cleanup-worktree.sh` | WorktreeRemove | Removes the worktree (force) and prunes the reference |

User-scope hooks at `~/.claude/hooks/` apply automatically — they don't need to be re-shipped. For example, a `stop-memory-check.sh` at user scope runs in this project too. Janus does not redundantly ship project-scope copies of hooks that work better at user scope.

## Skills

Bundled skills live under `skills/`. See each skill's `SKILL.md` for trigger conditions and `argument-hint`. To add a project-specific skill, drop it under `.claude/skills/<name>/SKILL.md`.

## Updating hooks

Hooks are **copied** (not symlinked) from janus at scaffold time, so customising per-project is intentional. To pull in upstream janus hook improvements later, diff against `templates/_shared/.claude/hooks/` in the janus repo and merge selectively.

## Format conventions

- `.tmpl` files use Mustache custom delimiters: `{{=<% %>=}}` pragma at top, then `<%NAME%>` for slots (lowercase identifiers — uppercase shown here so this doc isn't itself flagged by the smoke test). This delimiter choice avoids consuming GitHub Actions `${{ }}` expressions in workflow files.
- Hook scripts are bash; the `.tmpl` extension is dropped at render time. The scaffold restores the `+x` bit afterwards.
